# Persistent toggle buttons

ABI47 adds native-backed `toggle-button`, a WINDOW subclass for a push button
that stays pressed until toggled again. Each button is independent; this is not
a radio group or toolbar tool. Required `:parent` is a window, `:label` defaults
to an empty string and `:checked` defaults to NIL. Any non-NIL checked value means
pressed. Labels reject embedded NUL; empty/Unicode/mnemonic labels are supported
within native display conventions. Build requirement: wxUSE_TOGGLEBTN. Baseline:
wxWidgets3.2.12.

```lisp
(let ((preview (make-instance 'wxlambda:toggle-button :parent panel
                              :label "Live preview" :checked t)))
  (setf (wxlambda:checked-p preview) nil)           ; silent
  (setf (wxlambda:checked-p preview :notify t) t)   ; one update
  (setf (wxlambda:label-text preview) "Preview λ"))
```

`make-toggle-button` is a thin generic factory with validated `:class` and
forwarded subclass initargs. Direct subclasses support slot/default initargs and
native properties in AFTER hooks; invalid mixed native ancestry rejects and
managed initialization failures clean up widgets and callback roots. Lisp
subclassing does not implement native C++ virtual overrides. See
[CLOS API](CLOS-API.md).

## Checked state and label properties

Generic `checked-p` returns T/NIL; the reader ignores its shared `:notify` keyword.
SETF accepts a generalized boolean and returns the supplied value. Writes are
silent by default. `:notify t` commits then emits exactly one native-class
wxCommandEvent, even if the state is unchanged. Escaping callback conditions are
contained/re-signaled at the Lisp boundary; committed state is not rolled back.
Physical native delivery is not generated by silent writes.

Generic `label-text` reads native label text into an independent Lisp string.
Its SETF validates a NUL-free string and updates silently, preserving checked
state. Native mnemonic rendering/best-size behavior is port-specific; explicit
layout/size adjustment may be needed after changing text. No bitmap-toggle,
alignment/style, three-state, grouping or default-button behavior is exposed.

## Native toggle events and lifetime safety

Use `bind-event` with `:toggle-button-change`, optionally `:with-context t`.
This is a distinct command kind from checkbox `:toggle`. `event-checked-p`
provides copied/current checked metadata; `event-integer` is the raw native
integer. `event-text` copies the native payload, normally empty, and does not
infer the label. Explicit notifications also use empty text. `event-selection`
is NIL. Native command propagation supports frame observers; default observers
Skip automatically. There are no toggle-button ON-TOGGLE/OFF-TOGGLE convenience
methods; their existing checkbox methods retain their scope.

Immutable snapshots survive source destruction and session cleanup; borrowed
contexts require their innermost current callback and expire on return.
EVENT-CHECKED-P SETF is not supported for this kind. Raw current integer/text
metadata edits are observational, do not call the control setter, and do not
provide veto/rollback. Numeric/radio/toggle inputs share tracked-source guards:
same-button checked/label writes reject during its callback/operation, source and
ancestor destruction/close defer, and modal/clipboard/RUN/pump/nested safe-idle
entry reject until return. Silent writes to other buttons are supported. Actual
native-origin and propagated callbacks receive these guards, not just explicit
notifying setters. Creation/failure/base teardown suppress relevant callbacks.
Origins are matched by live registered identities/composite children, without
unchecked event-object pointer casts or dereferences.

Owned/synthetic construction, detached clone and queue/process-event injection
of this kind reject. No raw native pointer adoption, bitmap toggle subclass or
full native event/control parity is claimed. Existing CHECKBOX behavior is not
widened to the new resource by receiver fallback.

## Example and verification

[examples/toggle-buttons.lisp](../examples/toggle-buttons.lisp) keeps a preview
option pressed and updates feedback from checked snapshots. START is interactive;
EXERCISE uses silent and explicit notified writes, including unchanged values.

```sh
sbcl --load ~/quicklisp/setup.lisp --load examples/toggle-buttons.lisp --eval '(wxlambda-toggle-buttons:start)'
sbcl --noinform --non-interactive --load ci/setup.lisp --load tests/toggle-buttons.lisp
ccl --no-init --batch --load ci/setup.lisp --load tests/toggle-buttons.lisp
```

Lisp checks include CLOS construction/defaults/AFTER/rollback, Unicode label
properties, truthy values, safe callbacks, original condition identity and
committed state on callback errors, expired contexts/stale handles and post-session
snapshot reads. Native probes dispatch actual wxEVT_TOGGLEBUTTON events outside
setter operations, including parent propagation and both checked states; verify
source/ancestor/mutation/GUI-entry guards, cross-button updates and clone refusal.
These probes do not simulate physical mouse/key input. Runtime evidence is
macOS wxWidgets3.2.12; OSX/GTK/MSW/Qt native paths were source-reviewed. Hosted
platform GUI, physical input/accessibility and graphical Cadre remain unverified.
Automatic clipboard tests do not read/replace system contents. See
[coverage](WXWIDGETS-COVERAGE.md) and [Cadre installation](DOCSET.md).
